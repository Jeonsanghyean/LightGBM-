## 1. 기존 프로젝트와 확장 프로젝트 비교

### 1.1 기존 구현 상태 [측정]
- 시간순 분할: Train 1,037,340 / 검증 129,667 / 내부 비교 129,668 / Test 555,719. 계획서 수치와 일치함
- 특징 6개: `amt_ratio`, `count_5/15/60min`, `hour_rarity`, `insufficient_history`. 무작위 2,000건을 다시 계산해 모두 일치함
- LightGBM 전체 특징 AP: 내부 비교 0.4455, 원본 Test 0.3695
- 고액 결제 특징군 제거 시 AP 0.1124로 하락. 특징군 중 하락폭이 가장 큼
- 비용별 고정 임계값: 9개 조합 중 7개에서 총비용 감소
- Streamlit 연구 대시보드 4개 화면 구현

**표 1. 기존·확장 프로젝트 비교**

| 항목 | 기존 | 확장 |
|---|---|---|
| 데이터 | 미국 Sparkov | Sparkov + 한국 AI-Hub 카드거래 + 개인 거래 (저장소 분리) |
| 데이터 구조 | 원본 열 사용 | 공통 거래 스키마 + 필드 출처 표시 |
| 시간 정밀도 | 초 단위 | 초(미국·개인) / 1시간대(한국) / 날짜(개인 일부) |
| 특징 | 고액·반복·시간대 6개 | 기존 6개 유지 + 반복 보완 3개 + 위치 특징 |
| 모델 | 미국 모델 3종 | 국가별 모델 3종 + 국가 간 일반화 실험 |
| 설명 | 특징값 표 | 거래별 기여도 상위 3개 + 근거 문장 |
| 개인정보 | 해당 없음 | 로컬 전용 저장, 외부 전송 없음, 카드번호 차단 |

**표 2. 데이터셋 기본 정보**

| 항목 | 미국 Sparkov | 한국 AI-Hub 카드거래 합성데이터 |
|---|---|---|
| 출처 | Kaggle `kartik2112/fraud-detection` | AI-Hub 「이상 판별을 위한 금융거래 정보 및 사용자 패턴 합성데이터」 |
| 생성 방식 | 시뮬레이터 합성 | 하나카드 2021~2024 데이터 기반 합성 [확인] |
| 규모 | 1,852,394건 [측정] | 카드거래 2,169,857건 [확인] |
| 이상 비율 | 0.58% [측정] | 3.7% (80,009건) [확인] |
| 기간 | 2019-01 ~ 2020-12 [측정] | 2021 1분기 ~ 2024 4분기, 분기별 CSV 16개 [확인] |
| 이용 조건 | 로그인 없이 다운로드 가능 [측정] | 로그인 후 신청, **내국인만 가능**, 106.10MB [확인]. 재배포 범위는 약관 확인 필요 [미확인] |

**표 3. 필드별 비교와 처리 방법**

| 정보 | Sparkov | AI-Hub | 처리 |
|---|---|---|---|
| 거래 시각 | 초 단위 | `승인일자` + `승인시간대`만 있음 | 한국은 5·15·60분 특징 계산 불가 |
| 금액 | `amt` (USD) | `통합승인금액` (원화로 추정 [미확인]) | 통화 열로 구분 |
| 카드 | `cc_num` | `카드KEY` (가명) | 해시로 가명화 |
| 가맹점 이름 | `merchant`. 전 건이 `fraud_` 접두어로 시작 [측정] | 없음. `가맹점KEY`만 있음 | 한국은 NULL. 미국은 접두어를 제거해 표시만 하고 특징으로 쓰지 않음 |
| 업종 | `category` 14종 | `가맹점승인업종코드` (코드표 [미확인]) | 국가별 모델에서만 사용 |
| 온라인 여부 | `_net`·`_pos` 접미어에서 파생 (14종 중 6종만 판별) | `인터넷판매여부` | 미국은 "파생"으로 표시 |
| 가맹점 위치 | `merch_lat/long`. 같은 가맹점이 평균 433개 좌표를 가지며 카드 소유자 집 주변 ±1°에 무작위 분포 [측정] | `가맹점광역시도코드`만 있음 | 미국: 합성 좌표로 표시. 한국: 시도 단위로만 표시 |
| 가맹점 주소 | 없음 (`street`·`city`는 카드 소유자 주소) | 없음 | 둘 다 NULL |
| 이상 라벨 | `is_fraud` | `이상거래 여부`·`유형`·`설명` | 같은 정답으로 합치지 않음 (2.1절) |
| 민감 형태 정보 | 이름·생년월일·직업 (합성값) | 연령·성별 | 저장·사용하지 않음 |

### 2.1 라벨 의미 처리
- Sparkov는 시뮬레이터가 넣은 사기 거래이고, AI-Hub는 합성 과정에서 정의한 이상거래(유형 포함)임. 의미가 같은지는 [미확인]
- 국가별로 학습·평가를 분리함
- 국가 간 실험은 "위험 순위의 전이 정도"로만 해석함
- AP를 보고할 때 기준선(이상 비율)을 함께 적음. 두 데이터의 이상 비율이 6배 넘게 차이 나기 때문임
- AI-Hub 공식 기준 모델(SMOTE, F1)의 수치와 직접 비교하지 않음

### 4.1 개인 거래 위험도 분석 규칙 (F8)

**표 6. 개인 데이터 상태별 처리**

| 개인 데이터 상태 | 처리 |
|---|---|
| 시각이 분 단위 이상 | 미국 LightGBM 모델(기존 6개 특징)로 점수 산출. 특징이 단위 없는 상대값이라 통화와 무관함 |
| 시간대 또는 날짜만 있음 | **점수 보류** + 규칙 기반 "확인 권장" 목록만 표시 (6.3절 ③) |
| 카드별 과거 5건 미만 | 점수는 산출하되 "이력 부족" 경고 |

**위험 수준** (미국 LightGBM 고정 임계값 [측정])

| 수준 | 조건 |
|---|---|
| 높음 | 점수 ≥ 0.692 (5:1 임계값) |
| 주의 | 0.070 (100:1 임계값) ≤ 점수 < 0.692 |
| 낮음 | 점수 < 0.070 |

**출력 항목**
- 보정 전 점수와 Platt 보정 확률
- 기여도 상위 3개 특징: LightGBM `pred_contrib`, 추가 패키지 불필요
- 직전 거래와의 시간 간격·금액 비율
- 평소 패턴: 금액 중앙값, 자주 쓰는 시간대 3개
- 근거 문장. 예: "평소 결제액 중앙값의 8.3배", "최근 60분 안에 4건"

**분포 차이 점검**
- 각 특징이 학습 구간의 1~99 백분위를 벗어나는 비율을 계산함
- 30%를 넘으면 "학습 데이터와 분포가 다름" 경고를 표시함 (6.3절 ④)

**규칙 기반 확인 권장 조건**
- 금액이 평소 중앙값의 5배 이상
- 같은 날 같은 가맹점 3회 이상
- 하루 결제 건수가 평소 일평균의 3배 이상

**고정 안내문**: "위험도가 높다는 것은 사기 확정이 아니라 추가 확인이 필요하다는 뜻입니다."

## 6. 모델 및 특징 추출 개선안

### 6.1 특징 (`src/features_ext.py`)
- 기존 `build_features()` 결과에 새 특징을 덧붙임
- 모든 특징은 해당 거래 이전 이력만 사용함
- 계산할 수 없는 값은 0이 아니라 NaN으로 둠

**표 8. 특징 목록**

| 군 | 특징 | 미국 | 한국 | 개인 | 구분 |
|---|---|---|---|---|---|
| A 고액 | `amt_ratio` (기존) | ✓ | ✓ | ✓ | 필수 |
| B 반복 | `count_5/15/60min` (기존) | ✓ | 계산 불가 | 분 단위일 때 | 필수 |
| | `count_same_hour`, `count_same_day` (신규) | ✓ | ✓ | ✓ | 필수 |
| | `same_merchant_24h` (신규, 한국은 같은 날) | ✓ | ✓ (`가맹점KEY`) | 가맹점명이 있을 때 | 필수 |
| C 시간대 | `hour_rarity` (기존) | ✓ | ✓ | 시간이 있을 때 | 필수 |
| D 위치 | `dist_prev_km`, `speed_kmh`, `far_fast` (신규) | ✓ (합성 좌표) | NULL | NULL | 필수 |
| | `region_novelty`, `region_changed`, `is_overseas` (신규) | NULL | ✓ | — | 필수 |
| 공통 | `insufficient_history` (기존) | ✓ | ✓ | ✓ | 필수 |

- `speed_kmh`: 거래 간격이 1분 미만이거나, 두 거래 중 하나라도 온라인 거래면 NaN

- 속도 이상이 나와도 근거 문장에 "온라인·해외·가족카드 가능성 확인"을 함께 표시

### 6.3 1차 설계 대비 기술 변경

| 번호 | 1차 설계 | 변경 | 이유 |
|---|---|---|---|
| ① | 개인 주소를 동의 후 지오코딩해 지도 표시 | **외부 전송 기능 전부 제외**. 개인 거래는 시도 단위 표로만 표시 | 동의 관리가 필요 없어지고 위치정보 외부 전송 위험이 0이 됨 |

| ⑤ | 카드사별 열 매핑 프리셋 | 동의어 사전 자동 추정 + 수동 매핑 | 실제 명세서 샘플이 없어 프리셋을 검증할 수 없음 |
| ⑥ | 신규 특징 9개 + SHAP 중요도 집계 | 신규 특징 핵심 6종(표 8) + 거래별 기여도만 사용 | 일정 단축. 과제의 필수 특징은 모두 유지함 |

          models/ · outputs/v2 ────────► risk.py (점수·근거) ◄──┘
                 │
          Streamlit app_v2 (localhost 전용)
