## 1. 프로젝트 개요
- **기존(v1)**
  - 미국 Sparkov 모의 거래에서 고액·반복·이상 시간대 특징 6개로 LightGBM 사기 점수를 산출함
  - XGBoost·Logistic Regression과 비교함
  - 비용(오탐:미탐)별 경고 임계값을 고정 적용함
- **확장(v2)**
  - 공통 거래 스키마로 미국·한국·개인 데이터를 같은 구조로 다룸
  - 개인 카드 거래 입력·위험도 분석, 거래 조회·위치 지도, 위치·반복 보완 특징, 국가별 실험을 추가함
- **범위 밖**: 실시간 결제 연동, 사기 확정 판정, 개인 데이터를 이용한 재학습

## 2. 미국·한국 데이터 비교

## 3. 데이터 스키마
- 공통 거래 스키마 27개 필드 (`src/schema.py`)
  - 원본에 없는 값은 NULL로 둠
  - 다른 열에서 계산한 값은 `provenance`에 `derived`로 표시함 (미국 온라인 여부 등 100% 표시 확인 [측정])
- 연구 데이터는 `data/research/{us,kr}`의 Parquet 파일로 둠
- 개인 거래는 프로젝트 밖 `%LOCALAPPDATA%\CardFDS\personal.db`(SQLite)에 둠. 저장소를 물리적으로 분리함
- 한국 코드(시도·인터넷판매·승인거래)의 의미표는 `config/aihub_codebook.yaml`에 둠
  - 설명서로 확인하기 전까지 비워 둠 → 해당 필드는 NULL

## 4. 시스템 구조
```
Sparkov / AI-Hub / 개인 입력 → 출처별 변환·개인정보 검사 → 공통 스키마
  → 연구 데이터(Parquet) ─ 특징(v1 6개 + 신규) ─ 국가별 실험 ─ models/, outputs/v2
  → 개인 저장소(SQLite, 로컬) ─ risk.py(개인 점수용 모델·규칙) ─ 화면 6
Streamlit app_v2 (localhost): 1 데이터 선택 · 2 조회 · 3 지도 · 4 이상거래 분석 · 5 모델 성능 · 6 개인 거래
```
- 기존 `app.py`(v1)와 v1 코드는 수정하지 않음
- 회귀 테스트로 v1 결과가 바이트 단위로 동일함을 확인함 [측정]

## 5. 개인 거래 입력 방법
- **직접 입력**: 날짜·금액·통화는 필수, 시각은 권장, 가맹점·주소·유형·카드 별칭은 선택
- **CSV·Excel 업로드**
  - UTF-8·CP949 인코딩을 자동으로 판별함
  - 열 이름 동의어 사전으로 자동 매핑하고, 화면에서 사용자가 수정할 수 있음
  - 날짜·금액·시각 형식을 정규화하고, 중복 의심 거래를 기본으로 제외함
  - 형식이 틀린 행은 표에서 바로 수정할 수 있음
- **편집**: 수정·삭제·기간 검색, CSV·Excel 내보내기, 전체 삭제
- **보안**: 카드번호(Luhn 검사), 주민번호 형태, CVC 등의 열은 저장 전에 제거함

## 6. 거래 위치 분석
- **미국**
  - 카드별 결제 위치 지도, 직전 거래와의 거리·경과 시간·최소 평균 속도, 단시간 원거리 결제 여부를 보여줌
  - 온라인 결제는 속도를 계산하지 않음
- **한국**: 시도 단위 막대그래프로 표시함 (데이터 확보 후)
- **개인**
  - 주소에서 시도명만 뽑아 지역별 표로 보여줌
  - 지오코딩·외부 지도는 쓰지 않음. 개인 화면의 외부 요청 0건을 브라우저에서 확인함 [측정]
- **주의**: 미국 좌표는 무작위 합성값이라 직전 거래 거리 평균이 사기 104.0km, 정상 103.6km로 사실상 같음 [측정]

## 7. 특징 추출 방법
- v1 6개 특징은 그대로 씀: 금액 비율, 5·15·60분 건수, 시간대 희소성, 이력 부족 여부
- 신규 특징 10개를 추가함 (`src/features_ext.py`)
  - 직전 시간대 건수, 같은 날 앞선 건수, 24시간 내 같은 가맹점 반복
  - 직전 거래와의 거리·경과 시간·속도, 단시간 원거리 결제
  - 지역 새로움, 지역 변경, 해외 여부
- 모든 특징은 같은 카드의 이전 거래만 사용함. 같은 시각(한국은 같은 시간대) 거래는 서로의 이력으로 세지 않음
- 무작위 2,000건을 직접 다시 계산해 신규 특징 5종이 100% 일치함 [측정] (`outputs/v2/feature_checks_v2.csv`)

## 8. 모델 학습 및 성능 비교 [측정]
- **공통 설정**: 시간순 분할, 양성 가중치 10, 검증 구간에서 비용별 임계값 선택 후 원본 Test에 고정 적용
- **기준선**: 무작위 순위의 AP = 이상 비율. 내부 비교 구간 0.0064, 원본 Test 0.0039

### 8.1 미국 단독 (E1) — `e1_country_performance.csv`

| 특징 구성 | 모델 | AP 내부 비교 | AP 원본 Test | F1@0.5 내부 |
|---|---|---:|---:|---:|
| v1 6개 | LightGBM | 0.4455 | 0.3695 | 0.4194 |
| v1 6개 | XGBoost | 0.4450 | 0.3739 | 0.4103 |
| v1 6개 | Logistic Regression | 0.1977 | 0.1220 | 0.3663 |
| 확장 전체(16개) | LightGBM | 0.5353 | 0.4622 | 0.5048 |
| 확장 전체(16개) | XGBoost | **0.5684** | **0.4924** | 0.5309 |
| 확장 전체(16개) | Logistic Regression | 0.2080 | 0.1314 | 0.3812 |

- v1 설정은 기존 결과와 같게 재현됨 (0.4455)
- 확장 특징으로 LightGBM AP가 +0.0898(내부), +0.0927(Test) 올랐음
- 확장 특징에서는 XGBoost가 LightGBM보다 높았음

### 8.2 위치 특징 추가 효과 (E4·E4b) — `e4_location_effect.csv`, `e4b_location_decomposition.csv`

| LightGBM 특징 구성 | AP 내부 비교 | v1 대비 |
|---|---:|---:|
| v1 6개 | 0.4455 | — |
| v1 + 시간 간격만 | 0.4669 | +0.0214 |
| v1 + 거리만 | 0.4396 | **−0.0060** |
| v1 + 거리·속도·원거리 | 0.4798 | +0.0343 |
| v1 + 위치 특징 전체(D) | 0.4926 | +0.0470 |

- 거리만 추가하면 AP가 오히려 떨어졌음
- 위치 특징군의 효과는 거래 사이 **시간 간격**(속도 계산에 포함)에서 온 것으로 판단함
- 위치 정보 자체의 효과는 이 데이터로 확인할 수 없음 (좌표가 무작위 합성값)

### 8.3 특징군 기여도 (E5, 확장 전체 기준) — `e5_group_ablation.csv`

| 제거한 특징군 | AP 내부 비교 | 하락폭 |
|---|---:|---:|
| (없음) | 0.5353 | — |

| B 반복 | 0.4661 | 0.0691 |

- v1과 같이 고액 결제 특징의 기여가 가장 큼

### 8.4 비용 임계값 — `cost_thresholds_v2.csv`
- 8개 설정 × 3개 비용 비율 = 24개 조합 중 21개에서 검증 임계값이 기본 0.5보다 총비용을 낮춤
- 확장 LightGBM, 100:1: 총비용 87,729 → 65,683 (−25.1%)
- v1 LightGBM, 20:1: +0.1%로 효과 없음 (v1 결과와 같음)

### 8.5 확률 보정 — `e1_calibration.csv`
- LightGBM v1: Brier 0.0067 → 0.0032, LogLoss 0.0312 → 0.0157 (Platt 보정, 검증 구간 뒤 절반에서 평가)

### 8.6 한국·국가 간 [미측정]
- E2(한국 단독), E3(US↔KR 일반화), 한국 E4·E5, E6(유형별 Recall)은 데이터 미확보로 실행하지 않음 (`experiment_status.csv`)
- 변환기·특징 코드는 공식 열 정의로 만든 가짜 행으로만 단위 테스트함
- 실험 코드(E2·E3·한국 E4·E5·E6)는 준비됨(2026-11-28). 한국 특징 파일이 생기면 `python -m src.experiments_country`가 함께 실행하고 화면 5에 표시함. 가짜 행으로 끝까지 실행되는지만 테스트했고, 그 수치는 결과로 보고하지 않음
  - E2: 특징 2구성(v1 중 계산 가능한 3개 / 확장 전체 9개) × 모델 3종. 내부 비교 구간이 없어 테스트(2024) 구간으로 평가
  - E3: 공통 특징 5개 LightGBM, 나라별로 따로 학습. 임계값은 평가 국가 검증 구간에서 다시 고른 값과 학습 국가 값을 둘 다 보고
  - E4: 지역 특징(처음 보는 지역·지역 변경·해외 여부) 추가 전후, E5: 특징군 제거, E6: 비용별 검증 임계값에서 이상 유형별 Recall
- [예상] 한국은 분 단위 반복 특징이 없어 B군 기여가 미국보다 작을 수 있음. 국가 간 AP는 자체 학습보다 낮을 것으로 예상함

## 9. 개인 거래 위험도
- **점수 산출 대상**: 분 단위 시각이 있는 승인 거래만 모델 점수를 냄
- **점수 보류**: 날짜만 있는 거래, 취소 거래, 이력 5건 미만이면서 USD가 아닌 거래. 대신 규칙 기반 확인 항목을 보여줌
  - 평소 금액 중앙값의 5배 이상
  - 같은 날 같은 가맹점 3회 이상
  - 하루 건수가 평소 일평균의 3배 이상
  - 처음 쓰는 시간대
- **개인 점수용 모델**: v1에서 `hour_rarity`를 뺀 LightGBM
  - AP 내부 비교 0.3251, 원본 Test 0.2387 [측정] (`personal_model.csv`)
  - 임계값: 5:1은 0.712(높음), 100:1은 0.112(주의)
  - **이유**: Sparkov 학습 구간의 `hour_rarity`는 0.83~1.0에만 있음 (0.1% 분위 0.833) [측정]
    - 같은 시간대에 반복 결제하는 실제 사용자는 0에 가까운 값이 나와 모델이 본 적 없는 범위가 됨
    - v1 모델로는 매일 12시대 점심 결제 15건이 모두 '주의'로 나왔음 (브라우저 점검)
    - 바꾼 모델에서는 15건 모두 '낮음'이고, 새벽 3시 해외직구 고액 결제 2건이 '주의'·'높음'으로 나옴 [측정, 테스트용 데이터]
- **출력**: 보정 전 점수, Platt 보정 확률, 위험 수준, 기여 상위 3개 요인(LightGBM 기여값), 카드별 평소 패턴, 분포 차이 경고
- **고정 문구**: "위험도가 높다는 것은 사기 확정이 아니라 추가 확인이 필요하다는 뜻입니다."
- 개인 거래에는 정답 라벨이 없어 정확도를 계산하지 않음

## 10. 개인정보 보호 설계
- 카드번호·CVC·비밀번호를 저장하지 않음 (업로드 시 탐지·제거, 스키마에 열 없음)
- 개인 저장소는 OneDrive 밖에 두고, 폴더 권한은 사용자 계정 전용(icacls)
- 개인 데이터는 모델 학습 코드에서 읽지 않음 (테스트로 확인)
- 지오코딩·외부 지도를 쓰지 않음. Streamlit 사용 통계 전송을 끔. 서버는 localhost에서만 열림
- 사용자의 확인 결과("확인함 / 사기였음")는 같은 로컬 저장소의 별도 표에만 두고, 학습·점수 계산에 쓰지 않음
- 업로드 기록에는 파일 해시와 건수만 남김. 전체 삭제 시 VACUUM으로 파일 안 흔적까지 정리함
- AI-Hub 원본·가공본은 재배포하지 않고 집계 결과만 보고함

## 11. 실험 결과와 한계
- **[측정]**
  - 확장 특징이 미국 데이터에서 AP를 0.4455 → 0.5353(LightGBM), 0.5684(XGBoost)로 높였음
  - 가장 큰 기여는 고액 결제 특징임
- **한계**
  1. 미국 데이터는 모의 데이터이고 좌표가 무작위라, 위치 기반 탐지 효과는 검증하지 못함
  2. 한국 데이터 미확보로 국가별 비교·국가 간 일반화는 미측정
  3. 개인 점수는 미국 모의 데이터로 학습한 모델이라 실제 국내 이용 패턴에 맞는다는 근거가 없음. 정답이 없어 정확도도 측정할 수 없음
  4. 비용은 가정한 상대 단위이며 실제 피해액이 아님
  5. 지도 그림(WebGL)은 테스트 브라우저 캡처로 확인하지 못함. 지도 요소와 배경 타일 로드만 확인함

## 12. 향후 개선 방향
